# flix shell --pty 简报（L2 二期 · 交互式远程终端）

## 事实

- 一期 exec 已上线并通过真机验收：`rdShell` 信封、配对信任门、256KB 截断、超时杀进程树、中文输出、MCP `flix_shell`。
- 一期的限制：不分配 PTY，所以 `vim`/`top`/`ssh` 这类需要终端的程序不可用。
- 现有可复用：8891 通道、`pair_devices` 信任表、来源 IP 校验（文件传输已在用）、审计表。

## 范围

**In**：交互式 PTY 会话、CLI 入口、ConPTY（Windows）/pty（POSIX）、会话审计。
**Out**：多路复用与会话共享、网页/GUI 终端、端口转发、会话录制、非配对连接。

## 成功标准（可验收）

1. `flix shell --pty <对端>` 进入交互界面，能执行 `dir`、`cd`、`cls`。
2. 能运行全屏程序（如 `more`、`edit`），键盘/方向键/颜色正常。
3. 终端改窗口大小后，远端程序收到新的 cols/rows。
4. 未配对设备握手 → 403，不分配 PTY。
5. 目标端缺 pywinpty → 明确报错并提示改用 exec，不静默降级。
6. 会话结束写一条审计：发起方、时长、退出码。

## 主路径

CLI 建会话 → WS 握手 → 配对/来源校验 → ConPTY 分配 → 双向字节流 → 进程退出 → 释放并审计。

## 关键失败与人工出口

- 未配对 / 来源 IP 不符 → 403，人工查配对与网络。
- PTY 不可用 → 报错并建议 exec。
- 空闲超时 → 强制释放，人工看审计。

## 约束与风险

- 新增依赖 `pywinpty`（含原生 DLL）：PyInstaller 打包可能需额外 hiddenimports，必须在 EXE 上实测。
- 客户端要自己切 raw 模式并透传 ANSI；Windows 控制台需启用 VT 处理。
- 交互式会话不录制内容，只记元数据。
