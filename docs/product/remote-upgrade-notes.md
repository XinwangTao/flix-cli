# 异地升级 RelayDesk 的坑（2026-10-31 实测）

用 `flix shell` 远程升级对端的 exe 时踩到一次：换完文件、重启守护，进程起来了，
但新打包进去的原生依赖（`winpty.dll`）找不到，`/shell/pty` 一直 503。

## 根因

PyInstaller onefile 的进程会通过环境变量把解包目录传给子进程
（`_PYI_APPLICATION_HOME_DIR`，旧版本是 `_MEIPASS2`）。**从旧守护进程的命令通道里
启动新 exe，新进程继承了旧进程的解包目录**，于是复用了旧版解压出来的 DLL/数据，
exe 里新加的文件不会出现。

## 安全步骤

1. 换文件前把新包装到 Downloads，用不同文件名（同名会 409）。
2. 旧 exe 改名而不是覆盖（运行中的进程锁文件，改名可以；覆盖不行）。
3. 停 `serve` 进程时**只按 PID 停**，不要按进程名 `taskkill /T`，否则会连带杀掉
   正在执行升级的 shell 子进程。
4. 启动新进程前清空 `_PYI_APPLICATION_HOME_DIR` 和 `_MEIPASS2`，强制重新解包。
5. **启动后必须校验** `18991` 在监听；不监听就回退为"不清环境变量"的启动方式，
   保证 exec 通道至少还能用。
6. 清环境变量后的首次启动要重新解包（100 MB 左右），在带安全软件的机器上可能
   被杀软扫描拖慢甚至拦截——这一步失败时只有本机操作能救回来。

## 教训

远程升级必须带健康检查与回退路径；"文件替换成功"不等于"服务可用"。
