# flix upgrade 简报（L2 · 异地升级）

## 事实

- 现状：升级对端只能靠临时 PowerShell 脚本，已经踩过坑——从旧 onefile 进程里启动新进程会继承
  `_PYI_APPLICATION_HOME_DIR`，新打包的 DLL 不生效（见 `remote-upgrade-notes.md`）。
- 可复用：文件通道（带 409 检测）、`/intent` 命令通道、配对 + 来源 IP 校验、审计表。
- 约束：对端跑的是旧版本，不能假设它有升级逻辑，因此编排必须在发起端，对端只执行固定模板脚本。

## 范围

**In**：单台已配对设备的 exe 升级、包校验、备份改名、按 PID 停服、清环境启动、健康检查、自动回退、审计。
**Out**：配置/数据库迁移、批量升级、自动下载新版本、非 exe 文件、公网。

## 成功标准（可验收）

1. `flix upgrade <设备> --file RelayDesk.exe` 成功换包，对端 `18991` 在 30 秒内恢复监听。
2. 旧包保留为 `RelayDesk.exe.prev-<日期>`，可人工回退。
3. 新包启动失败时，脚本自动还原旧包并重启，命令通道恢复。
4. 本地包哈希与上传后对端收到的一致，回执里两者都打印。
5. 审计里有旧哈希、新哈希、耗时、是否回退。

## 主路径

本地校验 → 上传 → 下发固定脚本 → 改名+复制 → 清环境启动 + 健康检查 → 审计。

## 关键失败与人工出口

- 本地包不合规 → 拒绝，不动对端。
- 30 秒未就绪 → 自动回退旧包。
- 回退后仍不可用 → 只能本机启动（唯一人工出口）。

## 关键风险

- 停 `serve` 会短暂断开命令通道，属预期；重启后自动恢复。
- 默认**不清** PyInstaller 解包变量（实测有机器清掉后新进程起不来）；
  需要带新原生依赖的版本时显式加 `--fresh-env`，并准备人工兜底。
