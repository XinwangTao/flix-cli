# Flix CLI 重写项目 Brief（L2）

日期：2026-10-22  
状态：已确认（用户于 2026-10-22 确认）

## 1. 用户与目标

用户需要一套比当前软件更完整、更美观、可自动化的局域网设备协作工具，交互效率和信息架构参考本机已安装的 Flix，但使用自有品牌、界面资源和实现。首批同时服务于人工用户和 AI：桌面 GUI 负责可视化设备/会话/传输管理，`flix` CLI 与 MCP 负责脚本和 AI 调用，`flixd` 负责常驻设备能力。

“像 Flix”仅指可用工作流与能力组织方式，不复制 Flix 商标、图标、付费素材、云端账号体系或受保护资源。对本机官方客户端的逆向仅用于已授权的本地互操作验证；不绕过会员、认证或访问控制。

## 2. 已确认约束

- 后端采用双轨：默认保留官方 Flix 局域网协议兼容层，同时建设自有能力/协议层，避免未来被官方协议绑死。
- 首批端：Windows 桌面 + CLI/MCP；Android 先以当前 USB ADB 设备联调，当前已检测到 `192.168.236.61:5555`（`M2105K81AC`）。
- 首批能力：设备发现/配对、文本/图片/文件/目录传输、断点/取消/进度、群组与 `@设备`、剪贴板同步、ADB 文件/图片/文本/命令联调、远程观看/控制最小闭环、一对一音视频最小闭环。
- 远程命令默认必须人工明确批准；不允许配对后任意命令静默执行。ADB shell 也按设备授权和命令审计处理。
- 远程能力采用“可用闭环”：直连失败时降级为仅观看/仅文本，并显示原因；不承诺首批完全复刻官方所有高级媒体功能。
- 允许现代桌面技术栈；daemon/CLI/MCP 继续复用现有 Python 能力，GUI 与本机 API 解耦。

## 3. In Scope

1. `flixd`：发现、配对、设备会话、官方兼容通道、自有通道、传输任务、群聊路由、剪贴板同步、权限/审批事件和本机 API。
2. `flix` CLI：全部核心能力可命令行调用，稳定退出码、`--json`、进度/错误输出，适合 AI 脚本。
3. `flix mcp`：发现、设备状态、文本、文件、群组、剪贴板、审批状态和任务查询工具。
4. Windows 桌面 GUI：设备列表、配对确认、会话/群组、文件传输队列、预览/图片、剪贴板事件、命令审批、远程观看/控制、音视频会话状态。
5. Android/ADB 联调适配：设备探测、授权状态、push/pull、图片与文本、受控 shell、断线重连和测试报告。
6. 官方 Flix 互通：在已取证且不含未解协议的范围内验证发现、配对、文本、文件、剪贴板；未解能力必须标注兼容状态。
7. 自有协议能力：群组创建/成员管理、`@` 路由、任务状态、审批和能力协商。
8. 文档、协议证据、自动化测试和两台 Windows/一台 Android 的验收脚本。

## 4. Out of Scope

- 复制 Flix 品牌、界面资源、商业文案、会员能力或广告/统计 SDK。
- 自建公网账号、云端存储和中继服务；本批以局域网/USB ADB 为主。
- 绕过 Android/Windows 权限、ADB 授权、官方认证或 Flix MAX 限制。
- 首批完整实现扩展屏、复杂多方会议、低延迟游戏级串流、无人值守远程命令。
- 把官方协议中尚未取证的信令名称伪装成“已兼容”；这类能力先走自有协议或显示未实现。

## 5. 主场景与失败出口

### 场景 A：设备与群组

启动 `flixd` → 发现局域网设备 → 指纹/验证码配对 → GUI 或 CLI 创建群 → 添加已配对设备 → 发送带 `@设备` 的文本/任务 → 成员收到并可回执。

失败出口：无响应时显示网卡/防火墙/手动 IP 入口；指纹不一致时停止配对；成员离线时保留待发送状态并可重试或取消。

### 场景 B：文件、图片和剪贴板

CLI/MCP/GUI 选择对端或群 → 发送文件/目录或图片 → 接收端显示来源、大小和审批状态 → 接收/拒绝 → 分块传输、进度、校验、断点续传 → 完成后通知并写入安全目录。剪贴板同步有来源标记、哈希去回环和暂停开关。

失败出口：拒收、磁盘不足、路径冲突、校验失败、网络中断均保留任务状态；可恢复的任务继续/重试，不可恢复的任务给出人工操作指引。

### 场景 C：Android/ADB

选择已授权 USB 设备 → 检查序列号与授权 → 测试 shell 连通性 → push/pull 文件与图片、文本注入/读取 → 执行受控命令 → 采集 stdout/stderr/退出码/耗时 → 生成验收报告。

失败出口：未授权/离线/多个设备时禁止猜测目标；命令不在策略或未获批准时拒绝；USB 断开时保留任务并允许重连。

### 场景 D：远程观看、控制和音视频

能力探测 → 建立自有信令会话 → 用户明确批准屏幕/输入/麦克风/摄像头权限 → 优先直连 → 观看、有限键鼠控制或一对一音视频 → 结束并清理会话。

失败出口：权限不足、编解码器不可用或直连失败时降级为仅观看/仅文本；不自动开启摄像头、麦克风或输入注入。

## 6. 成功标准

1. 两台 Windows 上 `flix discover --json`、配对、状态查询均能稳定工作。
2. 文本、图片、单文件和目录可在自研端双向传输；大文件具备进度、取消、断点和校验，断线后能继续或明确失败。
3. 群组可创建、增删成员、发送普通消息和 `@` 定向消息；离线成员状态可见。
4. 剪贴板双向同步可暂停，远端写回不会形成回环。
5. 当前 Android 设备通过 ADB 完成 push/pull、图片、文本、shell、断线重连和报告验收。
6. 远程观看/控制和一对一音视频至少完成自研 Windows 双节点最小闭环；权限拒绝与直连失败有可见降级。
7. GUI、CLI、MCP 使用同一 daemon 状态和任务模型；所有 CLI 核心命令提供稳定 `--json` 与退出码。
8. 在已取证范围内与官方 Flix 完成发现/配对/文本/文件/剪贴板互通测试，并对未解能力给出明确报告。

## 7. 借鉴与取舍

- 借鉴 Flix：设备中心、气泡/任务式传输、群组会话、桌面 API 与实时事件。
- 借鉴 LocalSend/KDE Connect：能力声明、局域网发现、配对信任、分块传输和端到端可观测状态。
- 借鉴 RustDesk/Sunshine：直连优先、能力降级、权限显式化；不在本批引入公网中继。
- 自研：GUI 信息架构、群组 `@` 路由、CLI/MCP 契约、审批模型、ADB 联调适配和双轨协议抽象。

## 8. 实施顺序（确认后）

1. 建立 daemon 统一任务/事件模型和桌面 API 契约，保留当前兼容入口。
