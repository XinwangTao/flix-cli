# durable outbox 简报（L2 · 第一性原理改造）

## 第一性原理

这个产品的本质是**在局域网上把一段数据可靠地交给另一台机器**。可靠的含义有三条：
持久化、至少一次投递、显式 ack。今天缺的是前两条的半成品——只有 agent 消息有 outbox，
文本、文件、触发气泡都是"当场撞一次，撞不到就丢"。

真实证据（2026-10-31）：
- `[mic-status]` 触发气泡在对端离线窗口发出 → 超时 → 消息丢失，只能事后重发；
- 微信式的"发送成功"提示在气泡层面并不存在，只有 200 才算送达；
- 三次丢消息都发生在对端短暂离线（几十秒到几分钟）的窗口里。

## 范围

**In**：文本气泡的持久化、立即投递、失败排队、守护进程 30 秒重投、TTL、`flix outbox` 查看与手动处置。
**Out**：文件/剪贴板（二期）、非幂等动作重试、对端唤醒、跨进程写者、线格式变更。

## 成功标准（可验收）

1. 对端离线时 `flix send-text` 立即返回 `queued`（不阻塞、不报错），消息落库。
2. 对端上线后 30 秒内自动送达，`flix outbox` 状态变 `delivered`。
3. 未配对设备发送 → 4xx，不排队不重试。
4. 超过 TTL（默认 7 天）→ `expired`，不再重试。
5. `flix outbox --retry <id>` 可手动重投，`--drop <id>` 丢弃。
6. 全程不改官方线格式：发送仍是 `POST /bubble`，ack 仍是 200 `received bubble`。

## 主路径

写 outbox → 立即投递一次 → 200 标 delivered；失败标 queued → 后台 30 秒重投 → 送达或过期。

## 关键失败与人工出口

- 4xx：永久失败，标记 failed，不重试。
- 过期：标记 expired，人工重投或丢弃。

## 设计取舍

- **只对幂等的文本重试**：命令、升级这类动作重复执行有副作用，必须当场确认。
- **ack 语义收紧**：只有 200 `received bubble` 算送达，其它一律 queued。
- **一张表承接后续类型**：二期文件/剪贴板沿用 `outbox`，增加 `kind` 与 `ref`，不另起炉灶。
